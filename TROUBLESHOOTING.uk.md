# whisper-windows-mcp — Усунення несправностей

---

## Швидкий контрольний список

Перед детальнішим розслідуванням перевірте все нижченаведене:

- Шляхи в `claude_desktop_config.json` використовують **подвійний зворотній слеш** (`C:\\whisper\\...`)
- `whisper-cli.exe` існує за шляхом, вказаним у `WHISPER_CLI_PATH`
- Файл моделі `.bin` існує за шляхом, вказаним у `WHISPER_MODEL`
- FFmpeg встановлено і доступно (`ffmpeg -version` працює в командному рядку)
- Claude Desktop **повністю перезапущено** після редагування конфігурації (завершено з системного трея, а не просто закрито вікно)
- Сервер whisper відображається як **запущено** (зелений значок) у Налаштуваннях → Розробник

---

## "whisper не підключено" або інструменти недоступні

**Найпоширеніша причина:** Claude Desktop не було повністю перезапущено після редагування конфігурації.

1. Клацніть правою кнопкою миші на значку Claude в системному треї → Вийти
2. Повторно відкрийте Claude Desktop
3. Перейдіть до Налаштувань → Розробник і перевірте наявність зеленого значка **запущено** поруч з whisper

Якщо все одно не відображається:

1. Відкрийте `claude_desktop_config.json` і перевірте синтаксичні помилки JSON (відсутні коми, незбалансовані дужки)
2. Переконайтеся, що всі шляхи використовують подвійний зворотній слеш
3. Виконайте `check_config` у Claude Desktop, щоб отримати діагностичну інформацію

## download_model завершується тайм-аутом для великих моделей

Claude Desktop має 4-хвилинний тайм-аут для викликів інструментів MCP. Завантаження великих моделей на повільному з'єднанні може перевищити цей ліміт.

**Розміри файлів:**
- `large-v3` — 2.9 ГБ
- `large-v3-turbo` — 1.6 ГБ
- `large-v3-q5_0` — 1.1 ГБ
- `large-v3-turbo-q5_0` — 547 МБ
- `medium.en` — 1.5 ГБ
- `medium.en-q5_0` — 514 МБ

На швидкому з'єднанні (100 Мбіт/с і вище) навіть large-v3 завантажується менш ніж за 4 хвилини. На повільніших з'єднаннях використовуйте браузер або PowerShell для прямого завантаження і помістіть файл у теку моделей вручну:

```powershell
# Приклад — пряме завантаження large-v3-turbo
Invoke-WebRequest -Uri "https://huggingface.co/ggerganov/whisper.cpp/resolve/main/ggml-large-v3-turbo.bin" `
  -OutFile "C:\whisper\models\ggml-large-v3-turbo.bin"
```

Потім активуйте через `switch_model ggml-large-v3-turbo.bin`.

## `check_config` повідомляє, що whisper-cli.exe не знайдено

Шлях у конфігурації не збігається з фактичним розташуванням файлу.

Перевірте наявність файлу:
```
dir C:\whisper\Release\whisper-cli.exe
```

Якщо він знаходиться в іншому місці, оновіть `WHISPER_CLI_PATH` у конфігурації відповідно до фактичного шляху.

---

## `check_config` повідомляє, що FFmpeg не знайдено

FFmpeg не встановлено або його немає в системному PATH.

Встановлення через winget:
```
winget install ffmpeg
```

Або завантажте з [ffmpeg.org](https://ffmpeg.org/download.html), розпакуйте і додайте теку `bin` до системного PATH.

Після встановлення відкрийте новий командний рядок і перевірте:
```
ffmpeg -version
```

Якщо FFmpeg встановлено в нестандартному місці, задайте змінну середовища `FFMPEG_PATH` у конфігурації Claude Desktop:
```json
"env": {
  "FFMPEG_PATH": "C:\\ffmpeg\\bin\\ffmpeg.exe"
}
```

## Результат транскрипції заповнений тегами `[FOREIGN]`

**Причина:** Ви використовуєте модель лише для англійської (наприклад `ggml-medium.en.bin`) для не-англійського аудіо. Моделі лише для англійської не можуть опрацьовувати інші мови і виводять `[FOREIGN]` як замінник для кожного сегмента, який не можуть обробити.

**Виправлення:** Завантажте і використовуйте `ggml-large-v3.bin` — багатомовну модель. Вона необхідна для будь-якої не-англійської транскрипції, автовизначення мови або перекладу.

```
https://huggingface.co/ggerganov/whisper.cpp/resolve/main/ggml-large-v3.bin
```

Збережіть у `C:\whisper\models\` і оновіть конфігурацію:
```json
"WHISPER_MODEL": "C:\\whisper\\models\\ggml-large-v3.bin"
```

Або перевизначте для кожної транскрипції окремо за допомогою параметра `model` у `transcribe_audio` або `generate_subtitles`.

> **Примітка:** Моделі лише для англійської (`*.en.bin`) швидші і точніші для англійського контенту, але абсолютно не можуть опрацьовувати інші мови. Якщо ви працюєте з багатомовним контентом, `large-v3` — правильна модель незалежно від апаратного забезпечення.

---

## Транскрипція не дає результату або порожній файл

**Можливі причини:**

1. **Неправильна модель для мови** — Моделі лише для англійської (`*.en.bin`) не можуть транскрибувати інші мови. Використовуйте `ggml-large-v3.bin` для багатомовного контенту.

2. **Надто низька якість аудіо** — Файли з дуже низьким бітрейтом (наприклад, старі `.3gp` записи телефону з кодеком AMR-NB ~12 Кбіт/с) можуть бути на межі можливостей whisper. Шумні середовища (фоновий шум, луна, далекі доповідачі) також є проблематичними. Спробуйте `large-v3`, який краще справляється з деградованим аудіо.

3. **Файл тихий або пошкоджений** — Запустіть `analyze_media` для файлу, щоб перевірити, чи FFprobe виявляє дійсний аудіопотік.

4. **Помилка конвертування** — Файл може не конвертуватися у WAV правильно. Спробуйте конвертувати вручну:
```
ffmpeg -i yourfile.3gp -ar 16000 -ac 1 output.wav
```
Потім транскрибуйте WAV напряму.

## Фонове завдання не виконується для файлів з Unicode або спеціальними символами в назві

**Причина:** whisper-cli.exe не може записати вихідний файл, коли шлях містить символи Unicode (українські, японські, китайські, емодзі, дужки тощо) або певні спеціальні символи.

**Поточне обхідне рішення:** Перейменуйте файл, щоб використовувати лише ASCII-символи перед транскрипцією, а потім, якщо потрібно, перейменуйте назад.

```
ren "назва_файлу.mp4" "temp_transcribe.mp4"
```

**Статус:** Це відомий баг. Планується виправлення, яке буде спрямовувати вивід через санованный тимчасовий шлях і переміщати результат до правильного призначення після завершення.

---

## Фонове завдання показує "помилку" без результату

**Можливі причини:**

1. **Ім'я файлу з Unicode** — Дивіться вище.

2. **Неправильний шлях до моделі** — Відокремлений процес не успадковує виправлені шляхи. Виконайте `check_config` для перевірки шляхів.

3. **Процес було примусово завершено** — Якщо whisper-cli.exe було вручну зупинено під час завдання, вихідного файлу не буде. Повторіть спробу.

4. **Недостатньо VRAM** — Великі моделі на GPU з малим VRAM можуть тихо зазнавати збоїв. Спробуйте меншу модель.

5. **Помилка конвертування файлу** — Спробуйте транскрибувати WAV-файл напряму, щоб з'ясувати, чи проблема у конвертуванні чи у транскрипції.

---

## Фонова транскрипція не створює вихідний SRT

**Причина:** Фоновий режим (`background=true` у `transcribe_audio`) наразі виробляє лише `.txt`-вивід. Формат SRT у фоновому режимі ще не реалізовано.

**Обхідне рішення:** Для файлів менше ~4 хвилин використовуйте `generate_subtitles` у блокувальному режимі. Для довших файлів спочатку транскрибуйте у фоновому режимі, щоб отримати `.txt`, а потім, якщо потрібен SRT, виконайте `generate_subtitles` для того самого файлу (буде транскрибовано знову).

**Статус:** Підтримку SRT у фоновому режимі заплановано у майбутньому релізі.

---

## GPU не використовується (CPU постійно понад 50%)

**Причина:** Ви запускаєте бінарник лише для CPU, що постачається зі стандартним релізом whisper.cpp.

**Виправлення:** Завантажте збірку з підтримкою Vulkan зі [сторінки релізів](https://github.com/eviscerations/whisper-windows-mcp/releases/tag/v1.4.0) і розпакуйте в `C:\whisper\Release\`.

Перевірте, чи активне прискорення GPU:
- Попросіть Claude виконати `check_system`
- Знайдіть `✅ Vulkan binary: ggml-vulkan.dll found` у виведенні
- Спостерігайте за Диспетчером завдань → Продуктивність → GPU під час транскрипції — навантаження GPU має зрости до 15–30%

---

## `check_system` показує неправильний обсяг VRAM

Це відоме обмеження Windows. Команда `wmic` зчитує VRAM з реєстру, і на багатьох картах AMD відображає половину фізичного VRAM. Vega 56 з 8 ГБ HBM2 зазвичай показуватиме 4 ГБ. Це лише проблема відображення — whisper використовує весь фізичний VRAM під час виводу.

---

## Помилка "Транскрипція вже виконується"

Запущений процес `whisper-cli.exe` від попереднього завдання. Зачекайте його завершення або:

1. Відкрийте Диспетчер завдань → вкладка Відомості
2. Знайдіть `whisper-cli.exe`
3. Клацніть правою кнопкою миші → Завершити завдання

Потім повторіть спробу.

## Автовизначення мови дає неправильний результат

Автовизначення Whisper виконується за першими 30 секундами аудіо. Якщо файл починається іншою мовою, ніж більшість його вмісту, визначення може бути неправильним.

**Виправлення:** Вкажіть мову явно (наприклад `language=uk`), а не покладайтеся на автовизначення.

---

## Створення субтитрів дає "(говорить іноземною мовою)" по всьому відео

Whisper виявив мовлення, але не може транскрибувати. Найпоширеніші причини:

1. **Неправильна модель** — Використання моделі лише для англійської для не-англійського аудіо. Використовуйте `large-v3`.

2. **Якість аудіо** — Шумні середовища (кухні, натовп, луна) можуть бути складними для моделі medium. Спробуйте `large-v3`.

3. **Змішані мови** — Файли з двома мовами, що чергуються, матимуть меншоживану мову замінену заповнювачем при налаштуванні однієї мови.

---

## Переклад субтитрів дає лише англійський вивід

Це навмисна поведінка. Вбудований прапорець `--translate` Whisper перекладає **лише на англійську**. Для перекладу на інші цільові мови опрацьовуйте вміст `.srt`-файлу окремо.

---

## Пакетна транскрипція зупинила просування

Знову викличте `check_batch_progress`. Якщо все ще зависло:

1. Перевірте Диспетчер завдань на наявність запущеного процесу `whisper-cli.exe`
2. Перевірте журнали завдань у `%TEMP%\whisper-mcp-jobs\`
3. Файли зі збоями позначені у звіті пакету — запустіть їх окремо через `transcribe_audio`

---

## Очищення тимчасової теки завдань

whisper-windows-mcp записує файли стану завдань і журнали до `%TEMP%\whisper-mcp-jobs\` під час транскрипції. Вони накопичуються з часом і можуть займати місце на диску, особливо файли `.log` від тривалих завдань транскрипції.

Після завершення пакету або завдання і підтвердження вихідних транскрипцій ви можете безпечно видалити все в цій теці:

```powershell
Remove-Item "$env:TEMP\whisper-mcp-jobs\*" -Recurse -Force
```

Теку буде автоматично відтворено під час наступної транскрипції. Жодні вихідні файли транскрипцій не зберігаються тут постійно — вони переміщуються до вихідної теки після завершення. Залишаються лише метадані завдань і журнали.

**Примітка:** Не видаляйте цю теку під час виконання транскрипції — файли стану пакету необхідні для роботи `check_batch_progress`.

## Великий автономний пакет з командного рядка

Для дуже великих пакетів, де ви хочете запустити нічну роботу без Claude, використовуйте PowerShell.

**Важливо:** whisper-cli.exe не може безпосередньо читати MP4, MKV або більшість відеоформатів. FFmpeg повинен заздалегідь конвертувати кожен файл у WAV. whisper також записує транскрипцію у stdout, а діагностичний вивід — у stderr — використовуйте `Start-Process -RedirectStandardOutput` для правильного захоплення транскрипції. Використання pipe `|` або перенаправлення stderr через `2>$null` не захоплює нічого.

```powershell
$whisper = "C:\whisper\Release\whisper-cli.exe"
$model   = "C:\whisper\models\ggml-medium.en.bin"
$dir     = "C:\path\to\your\folder"
$ffmpeg  = "ffmpeg"
$tmp     = "$env:TEMP\whisper_convert.wav"

Get-ChildItem "$dir\*.mp4" | ForEach-Object {
    $out = ($_.FullName -replace '\.mp4$', '') + ".txt"
    if (Test-Path $out) {
        Write-Host "SKIP (exists): $($_.Name)"
        return
    }
    Write-Host "Converting:    $($_.Name)"
    & $ffmpeg -y -i $_.FullName -ar 16000 -ac 1 -c:a pcm_s16le $tmp 2>$null
    Write-Host "Transcribing:  $($_.Name)"
    $wArgs = "-m `"$model`" -f `"$tmp`" --threads 8 --condition-on-previous-text 0 --no-speech-thold 0.6"
    Start-Process -FilePath $whisper -ArgumentList $wArgs -RedirectStandardOutput $out -Wait -NoNewWindow
    Write-Host "Done:          $($_.BaseName).txt"
}

Remove-Item $tmp -ErrorAction SilentlyContinue
Write-Host "All done."
```

Замініть `*.mp4` на `*.mkv`, `*.m4a` тощо відповідно до типів ваших файлів. Перевірка пропуску `Test-Path` означає, що повторний запуск скрипту після переривання не переопрацьовуватиме вже завершені файли.

Це записує `.txt`-файли поруч з кожним джерелом. Інструменти MCP розпізнають їх як вже транскрибовані, коли ви потім виконаєте `analyze_media` або `start_batch`.

## Повний робочий приклад конфігурації

```json
{
  "mcpServers": {
    "whisper": {
      "command": "npx",
      "args": ["-y", "whisper-windows-mcp"],
      "env": {
        "WHISPER_CLI_PATH": "C:\\whisper\\Release\\whisper-cli.exe",
        "WHISPER_MODEL": "C:\\whisper\\models\\ggml-medium.en.bin",
        "FFMPEG_PATH": "ffmpeg"
      }
    }
  }
}
```

`FFMPEG_PATH` типово має значення `ffmpeg` (передбачається наявність у PATH). Задавайте явно лише якщо FFmpeg встановлено в нестандартному місці.
