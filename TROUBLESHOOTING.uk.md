# Усунення несправностей — whisper-windows-mcp

---

## Швидкий контрольний список

Перед детальнішим розслідуванням перевірте все нижченаведене:

- Шляхи в `claude_desktop_config.json` використовують **подвійний зворотній слеш** (`C:\\whisper\\...`)
- `whisper-cli.exe` існує за шляхом, вказаним у `WHISPER_CLI_PATH`
- Файл моделі `.bin` існує за шляхом, вказаним у `WHISPER_MODEL`
- FFmpeg встановлено і доступно (`ffmpeg -version` працює в командному рядку)
- Claude Desktop **повністю перезапущено** після редагування конфігурації (завершено з системного трея, а не просто закрито вікно)
- Сервер whisper відображається як **запущено** (зелений значок) у Налаштуваннях → Розробник

## Встановлення і запуск

### Whisper не з'являється в Claude Desktop → Налаштування → Розробник

1. Відкрийте Claude Desktop → Налаштування → Розробник → Редагувати конфігурацію
2. Переконайтеся, що JSON є дійсним — вставте його на [jsonlint.com](https://jsonlint.com) у разі сумніву
3. Переконайтеся, що `WHISPER_CLI_PATH` і `WHISPER_MODEL` вказують на файли, що фактично існують
4. Завершіть Claude Desktop з системного трея (клацніть правою кнопкою миші на значку → Вийти)
5. Перезапустіть Claude Desktop і перевірте знову

Якщо whisper з'являється, але показує значок помилки замість зеленого:
- Запитайте Claude: *"Перевір конфігурацію whisper"* — інструмент `check_config` повертає конкретне повідомлення про помилку
- Перевірте Claude Desktop → Налаштування → Розробник → клацніть на назві сервера для журналу помилок

### Помилка "whisper-cli.exe не знайдено"

Шлях у `WHISPER_CLI_PATH` не збігається з місцем розташування бінарника.

Очікуваний шлях за замовчуванням: `C:\whisper\Release\whisper-cli.exe`

Перевірте наявність файлу:
```powershell
Test-Path "C:\whisper\Release\whisper-cli.exe"
```

Має повернути `True`. Якщо повертає `False`, або розпакуйте реліз у `C:\whisper\Release\`, або оновіть `WHISPER_CLI_PATH` у конфігурації відповідно до фактичного розташування.

### Помилка "Модель не знайдена"

Шлях у `WHISPER_MODEL` не збігається з фактичним розташуванням або назвою файлу моделі.

Перевірте теку моделей:
```powershell
Get-ChildItem "C:\whisper\models\"
```

Назва файлу має включати повну назву разом із суфіксом квантизації, наприклад `ggml-large-v3-turbo-q5_0.bin`, а не `ggml-large-v3-turbo.bin`. Якщо моделі не встановлено, використовуйте `download_model` у Claude Desktop.

## Прискорення GPU

### Транскрипція повільна — лише CPU, без GPU

Запитайте Claude: *"Перевір апаратне забезпечення системи"*

Інструмент `check_system` підтверджує наявність `ggml-vulkan.dll` у теці бінарника whisper. Якщо DLL відсутній, ви працюєте лише на CPU незалежно від вашого GPU.

**Виправлення:** Завантажте `whisper-vulkan-win-x64.zip` зі [сторінки релізів](https://github.com/eviscerations/whisper-windows-mcp/releases/tag/v1.4.0) і розпакуйте в `C:\whisper\Release\`. Zip містить DLL — вона має знаходитися в тій самій теці, що і `whisper-cli.exe`.

### GPU визначено, але навантаження 0% під час транскрипції

Бінарник запущено, але не відправляє задачі на GPU. Зазвичай це означає:
- Vulkan SDK не встановлено або драйвер GPU не надає інтерфейс Vulkan
- GPU є старішим за Vulkan 1.0 (рідко — більшість GPU після 2016 року підтримують його)

Перевірте підтримку Vulkan:
```powershell
vulkaninfo
```

Будь-який вивід підтверджує доступність Vulkan. Якщо `vulkaninfo` не працює, встановіть останній драйвер GPU з сайту виробника.

### VRAM відображається як половина фактичного розміру (AMD)

Це відомий нюанс відображення Windows для GPU AMD з об'єднаною/спільною пам'яттю. Фактичний доступний VRAM для опрацювання зазвичай вдвічі більший за те, що повідомляє `wmic`. Рекомендація моделі може бути надмірно консервативною — ви можете спробувати більшу модель, ніж рекомендовано.

## Якість транскрипції

### Вивід містить галюцинований текст або повторювані фрази

Whisper іноді галюцинує на тихих або низькоякісних аудіосегментах. Інструмент за замовчуванням застосовує `--max-context 0` і `--no-speech-thold 0.6` для мінімізації цього.

Додаткові підходи:
- Використовуйте `temperature=0.2` — невелика випадковість допомагає розірвати цикли галюцинацій на шумному аудіо
- Використовуйте модель VAD: завантажте файл `.bin` моделі Silero VAD і передайте його шлях як `vad_model`. Це видаляє тишу перед транскрипцією — найефективніше виправлення для галюцинацій на записах з паузами.
- Використовуйте більшу модель (`large-v3` або `large-v3-turbo`) — менші моделі галюцинують більше на складному аудіо
- Використовуйте `prompt` для встановлення контексту: *"Це інтерв'ю подкасту про розробку програмного забезпечення."*

### Вивід транскрипції порожній або дуже короткий

Запитайте Claude: *"Проаналізуй цей файл"* (`analyze_media`), щоб підтвердити наявність аудіовмісту і розпізнаний формат.

Якщо FFprobe повідомляє про аудіо, але транскрипція нічого не виробляє:
- Файл може бути мовою, що не збігається з налаштованим параметром `language`
- Спробуйте `language=auto`, щоб Whisper визначив мову
- Аудіо може бути надто тихим або сильно обробленим — для транскрипції потрібна розбірлива мова

## Режим конфіденційності і ворота згоди

### Я не бачу запиту на згоду перед транскрипцією

Ворота згоди спрацьовують **один раз за сеанс** у стандартному режимі. Якщо ви вже підтвердили транскрипцію в цьому сеансі (після останнього перезапуску Claude Desktop), вони не спрацюють знову.

Інші причини, чому ворота можуть не з'явитися:
- `WHISPER_CONSENT_ACKNOWLEDGED=true` встановлено у вашій конфігурації — це повністю пригнічує ворота
- `WHISPER_PRIVACY_MODE=true` встановлено — режим конфіденційності використовує власні окремі ворота для кожної операції
- Ви перевіряєте прогрес блокувальної транскрипції, яка вже завершилась — ворота були використані на початку завдання

**Щоб скинути і знову побачити ворота:** повністю перезапустіть Claude Desktop (завершіть з системного трея, перезапустіть).

### Claude опрацьовує мій файл без запиту

Якщо `WHISPER_CONSENT_ACKNOWLEDGED=true` є у вашій конфігурації, ворота пригнічені навмисно. Це передбачена поведінка для користувачів, які ознайомилися з наслідками для конфіденційності.

Якщо це не встановлено і Claude продовжив без запиту, ворота сеансу вже були використані попередньою транскрипцією в цьому сеансі. Ворота спрацьовують один раз за сеанс.

Для підтвердження перед кожною транскрипцією незалежно від стану сеансу увімкніть режим конфіденційності: передайте `privacy_mode=true` або встановіть `WHISPER_PRIVACY_MODE=true` у конфігурації.

### Режим конфіденційності активний, але я хочу прочитати одну транскрипцію

Передайте `privacy_mode=false` безпосередньо інструменту транскрипції для цього конкретного виклику. Це перевизначає глобальне налаштування `WHISPER_PRIVACY_MODE=true` лише для одного виклику:

- *"Транскрибуй цей файл, privacy_mode=false"*

Перезапуск не потрібен. Перевизначення застосовується лише до цього одного виклику інструменту.

### Режим конфіденційності запитує підтвердження перед кожним файлом

Це правильна і навмисна поведінка. Режим конфіденційності вимагає згоди перед кожною операцією — ворота спрацьовують перед кожною транскрипцією і не можуть бути обійдені, поки режим конфіденційності активний.

Якщо вам потрібно транскрибувати багато файлів без підтвердження для кожного і контент не є чутливим, вимкніть режим конфіденційності:
- Видаліть `WHISPER_PRIVACY_MODE=true` з конфігурації і перезапустіть Claude Desktop
- Або передайте `privacy_mode=false` для конкретних нечутливих файлів

### Фонові завдання і ворота згоди

Для фонової транскрипції (`background=true`) у стандартному режимі ворота згоди спрацьовують при `check_progress`, коли повертається транскрипція — **не** при `transcribe_audio`, коли завдання запускається. На момент запуску завдання текст транскрипції ще не існує. Ворота спрацьовують у момент, коли текст транскрипції вперше повертається до API.

Для фонових завдань у режимі конфіденційності ворота спрацьовують **перед запуском** — до початку будь-якого аудіоопрацювання.

### Як назавжди пропустити ворота згоди?

Встановіть `WHISPER_CONSENT_ACKNOWLEDGED=true` у розділі env файлу `claude_desktop_config.json`. Це пригнічує одноразове розкриття сеансу у стандартному режимі.

Примітка: не має ефекту, коли режим конфіденційності активний.

## Фонова транскрипція і пакет

### Фонове завдання ніколи не показується як завершене

Стан завдання відстежується за виходом процесу whisper-cli.exe. Перевірте:

1. Запитайте Claude: *"Перевір прогрес job_id"* — якщо процес ще виконується, інструмент повертає "В процесі" з минулим часом і останньою міткою часу сегмента
2. Якщо файл дуже довгий (2+ години), дайте більше часу — транскрипція GPU 2-годинного файлу займає приблизно 15–20 хвилин на середньому GPU
3. Якщо минулий час здається неправильним, відкрийте Диспетчер завдань → Деталі і перевірте наявність `whisper-cli.exe` у списку

### Фонове завдання завершено, але вихідний файл відсутній або знаходиться не там

Фонові завдання записують вивід до тимчасового шляху в `%TEMP%\whisper-mcp-jobs\` під час опрацювання, а потім переміщують файл до вихідної теки після завершення. Якщо переміщення не вдається (диск повний, проблема з правами доступу або довжиною шляху), `check_progress` повертає конкретну помилку.

Перевірте:
- Вихідна тека існує і доступна для запису
- Достатньо місця на диску
- Цільовий шлях не надто довгий (Windows за замовчуванням має обмеження шляху в 260 символів)

Необроблений вивід може залишатися в `%TEMP%\whisper-mcp-jobs\` з іменем файлу на основі ID завдання.

### Пакет застряг або не переходить до наступного файлу

`start_batch` використовує зворотній виклик виходу для самостійного просування без опитування. Якщо пакет здається застряглим:

1. Викличте `check_batch_progress` — це примусово перевіряє прогрес і повторно оцінює поточний стан
2. Якщо поточний файл ще виконується, зачекайте його завершення — перевірте Диспетчер завдань на наявність `whisper-cli.exe`
3. Якщо `check_batch_progress` показує поточний файл як невдалий, він спробує перейти до наступного

### Пакет повідомляє файл як "невдалий", хоча він виглядає завершеним

Валідатор перевіряє, що вихідний файл не порожній і має принаймні один рядок на кожні 30 секунд аудіо. Короткі файли або записи з довгими тихими секціями можуть виробляти вивід, який валідатор вважає підозріло коротким.

Якщо транскрипція виглядає правильно при відкритті:
- Валідація є надмірно консервативною для цього файлу
- Повторно запустіть через `transcribe_audio` окремо і перевірте результат вручну

## Генерація субтитрів

### SRT-файл збережено, але з неправильною назвою або не там

SRT і VTT файли зберігаються поруч із вихідним файлом з доданим кодом мови, якщо мова джерела не англійська:
- Англійське джерело: `назвафайлу.srt`
- Українське джерело: `назвафайлу.uk.srt`
- З перекладом англійською: `назвафайлу.uk.srt` + `назвафайлу.en.srt`

### VTT-вивід для веб — як завантажити у десктопний плеєр?

VLC підтримує VTT через Субтитри → Додати файл субтитрів → вибрати `.vtt` файл. Більшість інших десктопних плеєрів краще підтримують SRT, ніж VTT. Використовуйте `output_format=srt` для максимальної сумісності з десктопними плеєрами.

VTT найкраще підходить для елементів HTML5 `<video>` і веб-відеоплеєрів.

### LRC-файли не відображаються у медіаплеєрі

LRC (`.lrc`) файли призначені для плеєрів з функціями відображення текстів/караоке: foobar2000, Winamp, AIMP та різні мобільні плеєри. Стандартні відеоплеєри не відображають LRC. Якщо вам потрібні синхронізовані субтитри для відео, використовуйте `srt` або `vtt`.

### CSV-вивід — який формат?

CSV-вивід включає час початку сегмента, час закінчення і текст у кожному рядку. Призначений для імпорту в табличні інструменти або скрипти аналізу нижнього рівня. Використовуйте `srt` або `vtt` для фактичного відображення субтитрів.

### Генерація субтитрів завершується тайм-аутом з помилкою 4 хвилини

`generate_subtitles` за замовчуванням виконується синхронно і може досягти 4-хвилинного тайм-ауту MCP Claude Desktop на довгих файлах. Використовуйте `background=true` для файлів понад 10 хвилин:

- *"Створи субтитри для цього файлу, background=true"*

Потім перевіряйте прогрес через `check_progress`. Примітка: `translate_to_english=true` недоступно у фоновому режимі. Виконайте другий прохід після завершення фонового завдання для генерації перекладу.

## Управління моделями

### `download_model` завершується мережевою помилкою

Інструмент завантажує з Hugging Face. Переконайтеся, що ваш комп'ютер має доступ до інтернету і `huggingface.co` не заблоковано брандмауером або проксі.

Якщо завантаження починається, але переривається, файл `.part` видаляється автоматично. Повторно запустіть `download_model` для повторної спроби.

### `switch_model` повідомляє, що модель не знаходиться в теці моделей

Інструмент `switch_model` приймає лише файли в теці, налаштованій у `WHISPER_MODEL` (зокрема, тека, що містить цей файл).

Якщо ваша модель знаходиться в іншому місці, або перемістіть її до теки моделей, або оновіть `WHISPER_MODEL` у конфігурації, щоб вказати на файл у тій самій теці, що і ваші моделі.

### Активна модель повертається до моделі з конфігурації після перезапуску Claude Desktop

`switch_model` є сеансовим за дизайном. Щоб зробити перемикання моделі постійним, оновіть `WHISPER_MODEL` у `claude_desktop_config.json` і перезапустіть Claude Desktop.

## Шляхи до файлів і формати

### Імена файлів Unicode спричиняють тихе невдале виконання транскрипції

Фонова транскрипція спрямовує весь вивід через санований ASCII-шлях на основі ID завдання, що правильно обробляє імена файлів Unicode. Якщо ви бачите збій з іменем файлу Unicode у блокувальному режимі, перевірте доступність файлу:

```powershell
Test-Path "C:\Users\ВашеІм'я\Documents\запис_наради.mp4"
```

Має повернути `True`. Якщо шлях недоступний для PowerShell, він також буде недоступний для MCP-сервера.

### Відеофайл не виробляє вивід або негайна помилка

FFmpeg потрібен для всіх відеоформатів. Переконайтеся, що FFmpeg встановлено:
```
ffmpeg -version
```

Якщо FFmpeg не в PATH, встановіть `FFMPEG_PATH` у конфігурації на повний шлях до `ffmpeg.exe`.

Якщо FFmpeg встановлено, але конкретне відео не вдається, це може бути пошкоджений файл або незвичайний варіант кодека. Спробуйте конвертувати вручну:
```
ffmpeg -i input.mp4 -ar 16000 -ac 1 output.wav
```
Потім транскрибуйте WAV-файл безпосередньо.

### Помилка "Файл надто великий"

Інструмент відхиляє файли понад 10 ГБ. Це обмеження безпеки для запобігання надмірному використанню пам'яті. Файли, що наближаються до цього розміру, слід розділити перед транскрипцією.

### Відхилення UNC-шляху

Шляхи, що починаються з `\\server\share` (UNC-шляхи до мережевих ресурсів), відхиляються валідатором вхідних даних. Підключіть мережевий ресурс як літеру диска (наприклад `Z:\`) і використовуйте цей шлях.

## Очищення тимчасових файлів

Файли стану завдань (`.json` і `.log`) у `%TEMP%\whisper-mcp-jobs\` автоматично очищуються при запуску для файлів старших 7 днів. При необхідності можна виконати ручне очищення:

```powershell
Remove-Item "$env:TEMP\whisper-mcp-jobs\*" -Force
```

Тимчасові WAV-файли конвертування (`whisper_tmp_*.wav` у `%TEMP%`) видаляються одразу після завершення кожної транскрипції. Якщо транскрипція аварійно завершилась, вони можуть залишитися. Видаліть їх вручну:

```powershell
Remove-Item "$env:TEMP\whisper_tmp_*.wav" -Force
```

## Великий автономний пакет з командного рядка

Для дуже великих пакетів без Claude використовуйте PowerShell безпосередньо.

**Важливо:** whisper-cli.exe не може безпосередньо читати MP4, MKV або більшість відеоформатів. FFmpeg має попередньо конвертувати кожен файл у WAV. Whisper записує транскрипцію у stdout, а діагностику у stderr — використовуйте `Start-Process -RedirectStandardOutput` для правильного захоплення.

```powershell
$whisper = "C:\whisper\Release\whisper-cli.exe"
$model   = "C:\whisper\models\ggml-medium.en.bin"
$dir     = "C:\шлях\до\вашої\теки"
$ffmpeg  = "ffmpeg"
$tmp     = "$env:TEMP\whisper_convert.wav"

Get-ChildItem "$dir\*.mp4" | ForEach-Object {
    $out = ($_.FullName -replace '\.mp4$', '') + ".txt"
    if (Test-Path $out) {
        Write-Host "ПРОПУСК (існує): $($_.Name)"
        return
    }
    Write-Host "Конвертування:    $($_.Name)"
    & $ffmpeg -y -i $_.FullName -ar 16000 -ac 1 -c:a pcm_s16le $tmp 2>$null
    Write-Host "Транскрипція:  $($_.Name)"
    $wArgs = "-m `"$model`" -f `"$tmp`" --threads 8 --max-context 0 --no-speech-thold 0.6"
    Start-Process -FilePath $whisper -ArgumentList $wArgs -RedirectStandardOutput $out -Wait -NoNewWindow
    Write-Host "Готово:          $($_.BaseName).txt"
}

Remove-Item $tmp -ErrorAction SilentlyContinue
Write-Host "Все готово."
```

Замініть `*.mp4` на `*.mkv`, `*.m4a` тощо відповідно до типів ваших файлів. Перевірка пропуску `Test-Path` означає, що повторний запуск скрипту після переривання не переопрацьовуватиме вже завершені файли.

## Повний робочий приклад конфігурації

```json
{
  "mcpServers": {
    "whisper": {
      "command": "npx",
      "args": ["-y", "whisper-windows-mcp"],
      "env": {
        "WHISPER_CLI_PATH": "C:\\whisper\\Release\\whisper-cli.exe",
        "WHISPER_MODEL": "C:\\whisper\\models\\ggml-medium.en.bin",
        "FFMPEG_PATH": "ffmpeg"
      }
    }
  }
}
```

`FFMPEG_PATH` типово має значення `ffmpeg` (передбачається наявність у PATH). Задавайте явно лише якщо FFmpeg встановлено в нестандартному місці.
