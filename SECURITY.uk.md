# Політика безпеки

## Область охоплення

whisper-windows-mcp — інструмент з пріоритетом локальності. Все аудіоопрацювання відбувається на вашому комп'ютері — жодні аудіо-, відеофайли чи персональні дані не передаються на жодний сервер. Поверхня атаки обмежена:

- Локальна файлова система (шляхи до файлів, що передаються інструментам)
- Бінарник whisper-cli.exe та його залежності
- З'єднання Claude Desktop MCP (лише локальний IPC)
- Текст транскрипції, що повертається у відповідях інструментів (дивіться Архітектуру конфіденційності нижче)

## Архітектура конфіденційності

**Аудіофайли ніколи не покидають ваш комп'ютер.** Ця гарантія є безумовною.

**Текст транскрипції може покидати ваш комп'ютер** у стандартному режимі. Коли відповідь інструменту містить текст транскрипції, цей текст опрацьовується API Claude. Це стандартна поведінка MCP, але вона створює розрив між філософією дизайну "локальний пріоритет" і фактичним потоком даних для користувачів, що працюють з регульованим або конфіденційним контентом.

**Режим конфіденційності** (`WHISPER_PRIVACY_MODE=true` або `privacy_mode=true` для окремого виклику) обмежує всі відповіді інструментів лише метаданими — жодний текст транскрипції не повертається API Claude. Це правильне налаштування для медичних, юридичних, фінансових і корпоративних розгортань.

**Ворота режиму конфіденційності:** коли режим конфіденційності активний, перед кожною операцією транскрипції відображається явне підтвердження розкриття, ключоване за операцією (інструмент + аргументи). Сервер забезпечує *блокування* — він утримує операцію і повертає розкриття при першому виявленні заданої операції. Він **не** забезпечує, що відповіла людина: ворота відкриваються, коли той самий виклик повторюється, з припущенням, що хост показав розкриття, а користувач відповів «так». Клієнт, який повторює той самий виклик без участі людини, може задовольнити ворота самостійно. Сприймайте це як процедурний засіб контролю поінформованої згоди, що залежить від дотримання розкриття MCP-хостом, а не як криптографічний бар'єр.

**Ворота згоди:** у стандартному режимі одноразове розкриття для сеансу відображається перед першим поверненням тексту транскрипції до API. Встановіть `WHISPER_CONSENT_ACKNOWLEDGED=true` у конфігурації, щоб пропустити це для нечутливого контенту. Зауважте, що це ворота *один раз за сеанс*: після першої підтвердженої транскрипції наступні транскрипції в тому самому сеансі повертаються без повторного запиту. Використовуйте режим конфіденційності для контенту, який ніколи не має досягати API, незалежно від стану сеансу.

Повний опис архітектури конфіденційності, настанови щодо нормативних вимог (HIPAA, GDPR, адвокатська таємниця, FERPA, SOX, PCI-DSS) та інструкції з налаштування — у [PRIVACY.md](PRIVACY.md).

## Перевірка бінарника

Щоб перевірити цілісність бінарника `whisper-cli.exe` у готовому релізі, перевірте його хеш SHA256 у PowerShell:

```powershell
Get-FileHash "C:\whisper\Release\whisper-cli.exe" -Algorithm SHA256
```

Очікуваний хеш для кожного релізного бінарника опубліковано на [сторінці релізів](https://github.com/eviscerations/whisper-windows-mcp/releases). Не використовуйте бінарник, хеш якого не збігається.

## Повідомлення про вразливість

**Не відкривайте публічний issue для вразливостей безпеки.**

Використовуйте приватну звітність про вразливості GitHub:
1. Перейдіть до [вкладки Security](https://github.com/eviscerations/whisper-windows-mcp/security)
2. Натисніть "Report a vulnerability"
3. Опишіть проблему з достатніми деталями для відтворення

Ви отримаєте відповідь протягом 7 днів. Якщо вразливість підтверджено, виправлення буде випущено якнайшвидше, і вас буде вказано в примітках до релізу за вашим бажанням.

## Пісочниця та схвалення

whisper-windows-mcp — це **локальний інструмент для одного користувача, який керується власником комп'ютера через Claude Desktop.** Його модель загроз — це власник, який запускає його на власному комп'ютері — а не ненадійне, багатоорендне або відкрите в мережу розгортання.

- **Пісочниця:** відсутня, за задумом. `whisper-cli.exe` запускається на рівні прав самого власника, так само як будь-який локальний MCP-сервер. Засобом пом'якшення тут є не ізоляція на рівні ОС, а сфера використання — **не відкривайте цей сервер для ненадійного мережевого доступу** (див. «Ін'єкція шляху до файлу» нижче).
- **Схвалення є багаторівневими, а не на основі пісочниці:**
  1. **Схвалення хоста** — рівень MCP Claude Desktop контролює виклик інструментів.
  2. **Бар'єри згоди / конфіденційності** — перед тим, як будь-який текст транскрипції залишить комп'ютер у напрямку API Claude, потрібне явне підтвердження; `WHISPER_PRIVACY_MODE` / `privacy_mode` для окремого виклику повертає лише метадані для регульованого контенту. Бар'єр ключований за операцією (інструмент + аргументи). Дивіться [PRIVACY.md](PRIVACY.md).
  3. **Перевірка вводу** — застосовується захисно в кожному інструменті, що приймає шлях або ID:
     - Шляхи з обходом каталогів (`..`) і UNC (`\\server\share`) відхиляються на **всіх** файлових/тековий вводах, включно з `analyze_media` і `transcribe_batch` (два останніх раніше перевіряли лише існування — неперевірений UNC-шлях міг спричинити вихідне SMB-з'єднання до хоста зловмисника).
     - `job_id` / `batch_id` перевіряються на відповідність точному формату, згенерованому сервером, перш ніж їх використовують для побудови будь-якого шляху файлової системи, тож сфабрикований ID не може вийти за межі теки завдань до довільного читання/запису/видалення файлів.
     - І `switch_model`, **і** перевизначення `model` у `transcribe_audio` обмежені налаштованою текою моделей через нормалізоване утримання шляхів — перевизначення не можна використати, щоб підсунути `whisper-cli` довільний файл як модель.
     - Шляхи `vad_model` відхиляють обхід/UNC.
     - `download_model` обмежено списком дозволених довірених просторів імен Hugging Face (початковий URL і кожне переспрямування).
     - Системні бінарники Windows, які сервер викликає неявно (`tasklist`, `wmic`), викликаються за абсолютним шляхом `System32`, тож їх не може підмінити однойменний виконуваний файл, розміщений раніше в `PATH`.

**Примітка про межу «ненадійного агента».** Цей інструмент розроблено для одного власника, який керує ним через Claude Desktop, а не як спільна чи відкрита в мережу інфраструктура. Однак транскрибований аудіо-/відеоконтент сам є ненадійним вводом, який може *нагадувати інструкції* і впливати на те, які інструменти викликаються далі і з якими аргументами (див. «Ін'єкція транскрипції» нижче). Через це перевірка вводу вище застосовується захисно, а не покладається виключно на припущення про одного користувача. Повністю ненадійна-агентна або багатоорендна позиція все одно вимагала б пісочниці ОС/контейнера та політики вихідного трафіку — поза межами локального інструмента транскрипції для одного користувача.

## Відомі проєктні рішення

- **Ін'єкція шляху до файлу:** Інструменти приймають абсолютні шляхи до файлів від Claude. Це навмисний дизайн — інструмент призначено для використання власником комп'ютера разом з Claude Desktop. Обхід (`..`) і UNC-шляхи відхиляються в усіх інструментах, що приймають шляхи; абсолютні локальні шляхи в іншому разі приймаються. Не відкривайте цей MCP-сервер для ненадійного мережевого доступу.
- **Перевірка ID завдання/пакету:** `job_id` і `batch_id` мають відповідати точній формі, згенерованій сервером (`job_<epochMs>_<8 hex>` / `batch_<epochMs>_<8 hex>`), перш ніж їх використовують для побудови будь-якого шляху файлової системи. Це запобігає виходу сфабрикованого ID за межі теки завдань до довільного читання, запису або видалення файлів через обробку завершення завдання.
- **Ворота згоди/конфіденційності є процедурними:** Ворота залежать від того, що MCP-хост показує розкриття, а людина відповідає перед повторним викликом операції. Сервер забезпечує поведінку блокування-до-повторного-виклику, але не може перевірити, що відповіла людина. Для контенту, який ніколи не має досягати API, покладайтеся на режим конфіденційності (відповіді лише з метаданими), а не на самі ворота.
- **Відсутність пісочниці:** whisper-cli.exe запускається з тими самими правами, що і Claude Desktop. Це стандарт для локальних MCP-інструментів.
- **Тимчасові файли:** Проміжні WAV-файли записуються до `%TEMP%\whisper_tmp_*.wav` і видаляються після транскрипції. Файли стану завдань записуються до `%TEMP%\whisper-mcp-jobs\` і автоматично очищуються через 7 днів при запуску сервера.
- **Вміст транскрипції:** Текст транскрипції, що повертається у відповідях інструментів, опрацьовується API Claude у стандартному режимі. Увімкніть `WHISPER_PRIVACY_MODE=true` або передайте `privacy_mode=true` для окремого виклику, щоб запобігти цьому. Дивіться [PRIVACY.md](PRIVACY.md).
- **Ін'єкція транскрипції:** Аудіофайли можуть містити вимовлений контент, який після транскрипції нагадує інструкції. Вбудований захист Claude впорається з цим. Сам MCP-сервер позначає весь вміст транскрипції як ненадійні дані і ніколи не інтерпретує їх як інструкції.
- **Завантаження моделей:** Інструмент `download_model` завантажує лише з двох довірених просторів імен Hugging Face (`ggerganov/whisper.cpp` і `ggml-org`). Переспрямування перевіряються за списком дозволених перед виконанням. Довільні URL-адреси відхиляються на рівні коду. Обрізані/неповні завантаження відхиляються (перевірка Content-Length) перед тим, як файл `.part` буде підвищено до імені моделі. **Наступний крок:** завантаження ще не перевіряються за дайджестом SHA256 для кожної моделі, тож скомпрометований джерельний сервер або атакувальник на шляху все ще може підсунути шкідливий `.bin`. Закріплені дайджести заплановано; для розгортань з високими вимогами до гарантій перевіряйте хеші вручну за сторінкою релізів.
- **Утримання вибору моделі:** І `switch_model`, і перевизначення `model` у `transcribe_audio` приймають лише `.bin`-файли з налаштованої теки моделей. Шляхи за її межами відхиляються через нормалізоване утримання шляхів — каталог із братнім префіксом, такий як `…\models-evil`, не може задовольнити перевірку — незалежно від способу вказання шляху. Шляхи `vad_model` відхиляють обхід/UNC.
- **Неявні системні бінарники:** `tasklist` і `wmic` викликаються за абсолютним шляхом `System32`, а не за голим іменем, тож їх не може підмінити однойменний виконуваний файл, розміщений раніше в `PATH`.
- **Постійний сервер моделі:** необов'язковий інструмент `whisper_server` запускає `whisper-server` від whisper.cpp як резидентний процес. Він прив'язаний лише до `127.0.0.1` — ніколи до маршрутизованого інтерфейсу — тож недосяжний поза комп'ютером. Він запускається і зупиняється явно (ніколи не автозапускається), а власний процес завершується при вимкненні. Оскільки резидентний сервер і одноразовий `whisper-cli` конкурували б за той самий GPU/VRAM, вони взаємно виключні: жорсткий запобіжник у шляху відокремленого запуску не дає жодному CLI-завданню запуститися, поки сервер працює, а інструменти транскрипції відхиляють операції, що потребували б CLI, доки сервер не зупинено. `WHISPER_SERVER_PORT` вибирає localhost-порт; хост не налаштовується за задумом.
