# whisper-windows-mcp — Дорожня карта

Поточна версія: **v2.2.0**

## Принципи проєктування

Ці принципи визначають кожне рішення в цьому проєкті і мають пріоритет над швидкістю додавання функцій.

**Мінімізація використання Claude API.** Весь робочий процес транскрипції — сканування, аналіз, черга, виконання, перевірка, перемикання моделей — має виконуватися з мінімальною кількістю взаємодій з Claude. Цей інструмент має повноцінно працювати для користувачів безкоштовного плану Claude, які не платять за підписки Pro або Max. Кожен виклик інструменту витрачає ліміт використання. Проєктуйте відповідно.

**Завжди лише один екземпляр whisper.** Ніколи не запускайте другий процес whisper-cli.exe, поки один вже виконується. Блокування процесу є обов'язковим і не підлягає переговорам.

**Локальний пріоритет, приватно за замовчуванням.** Аудіо ніколи не покидає комп'ютер. Для основних функцій хмарні API не потрібні. Необов'язкові інтеграції (наприклад, завантаження моделей з Hugging Face) мають бути чітко задокументовані як необов'язкові.

**Явний контроль користувача.** Жодних тихих масових операцій. Руйнівні або незворотні дії потребують підтвердження. Користувач завжди має знати, що відбуватиметься, до того, як це станеться.

**Unicode-безпечні шляхи.** Весь файловий введення-виведення має правильно обробляти не-ASCII імена файлів, включно з українськими, японськими, китайськими, емодзі, дужками та іншими спеціальними символами.

**Модульність і компонованість.** Інструменти незалежні. Користувачі використовують те, що їм потрібно. Жодна функція не повинна вимагати іншої, якщо цього неможливо уникнути.

**Оптимізація перед функціями.** Якщо сумніваєтеся між додаванням функції та зменшенням навантаження на систему або кількості викликів API — зменшуйте навантаження. Великі оптимізаційні роботи дорого коштують. Спроєктуйте архітектуру правильно з першого разу.

## Критична помилка — Автоматичне просування пакету (підтверджено, очікує виправлення)

### Пакет не просувається без активного опитування

`start_batch` не просуває чергу автономно між файлами. Пакет просувається лише при виклику `check_batch_progress`. Без опитування пакет зависає на невизначений час після кожного файлу — whisper-cli.exe завершується, новий процес не запускається, черга не просувається.

Це підриває мету дизайну автономної нічної пакетної обробки і безпосередньо порушує принцип мінімізації викликів Claude API. Пакет з 95 коротких кліпів вимагав близько 200 викликів опитування протягом 100 хвилин для завершення.

**Корінна причина:** `readBatchProgress` містить всю логіку просування черги. Він виконується лише при явному виклику `check_batch_progress`. Немає фонового таймера, спостерігача файлів або автономного циклу.

**Заплановане виправлення — Варіант Б (зворотній виклик виходу, наполегливо рекомендовано):** Прикріпити обробник `on('exit')` до породженого дочірнього процесу whisper-cli. Коли процес завершується, негайно викликати логіку просування для перевірки виводу і запуску наступного завдання. Подієво-орієнтований, спрацьовує рівно один раз при завершенні кожного файлу, нульові витрати на опитування, нуль спожитих викликів API.

**Варіант А (лише резервний):** Фоновий `setInterval` з інтервалом опитування на основі тривалості, виведеним з даних тривалості FFprobe, вже наявних у JSON стану пакету. Розмір файлу не є надійним замінником тривалості.

**Додаткове обмеження:** Виправлення не повинно породжувати другий whisper-cli.exe, поки один вже виконується — блокування процесу має дотримуватися в шляху автопросування.

**Обхідне рішення (поточне):** Повторно викликайте `check_batch_progress` до завершення пакету. Приблизно один виклик опитування на файл.

## Заплановано — Архітектура конфіденційності (до міграції на Bun)

Ці зміни мають бути випущені до міграції на Bun і до будь-яких змін ліцензії, що сприяють комерційному або корпоративному прийняттю. Випуск інструментів корпоративного рівня без вирішених засобів захисту відповідності створює відповідальність для користувачів у регульованих галузях.

### Змінна середовища `WHISPER_PRIVACY_MODE`
Інструмент наразі гарантує, що жодне **аудіо** не покидає комп'ютер. Ця гарантія не поширюється на **текст транскрипції** — коли вміст транскрипції повертається в рядку у відповіді інструменту, цей текст опрацьовується API Claude і покидає локальне середовище.

Цей розрив невидимий для користувачів, які розумно тлумачать "дані не покидають ваш комп'ютер" як таке, що охоплює весь контент, отриманий з їхнього аудіо.

Додати `WHISPER_PRIVACY_MODE` як змінну середовища у `claude_desktop_config.json`. При увімкненні:
- Усі відповіді інструментів повертають лише метадані: ім'я файлу, тривалість, кількість слів, статус завершення
- Жоден текст транскрипції не включається до жодної відповіді інструменту
- Claude не може читати, аналізувати або передавати вміст транскрипції в жодній формі
- Транскрипція існує лише як локальний `.txt`-файл

Це правильне рішення для медичних, юридичних, фінансових і корпоративних розгортань. Нуль викликів API, нуль передачі даних, нуль ризику відповідності.

### Ворота згоди для вмісту транскрипції
Коли `WHISPER_PRIVACY_MODE` не увімкнено (типово), будь-яка відповідь інструменту, що містить текст транскрипції, має передуватися повідомленням про розкриття інформації при першому використанні за сеанс. Це повідомлення має чітко передати, що текст транскрипції передається до API Anthropic, що це виходить за межі гарантії "дані не покидають ваш комп'ютер", і що користувачі, які працюють з регульованим контентом, мають перевірити зобов'язання відповідності перед продовженням.

Реалізація: змінна середовища `WHISPER_CONSENT_ACKNOWLEDGED` за замовчуванням `false`. При першому поверненні транскрипції за сеанс, якщо не підтверджено, Claude представляє повідомлення про розкриття і просить явного підтвердження. Після підтвердження для сеансу наступні транскрипції повертаються без повторного запиту.

### Документація `PRIVACY.md`
Створити `PRIVACY.md` у кореневій теці репозиторію:
- Які дані завжди залишаються локально: аудіо, відео, файли моделей
- Які дані можуть покидати локальне середовище (за замовчуванням): текст транскрипції у відповідях інструментів
- Які дані ніколи не покидають локальне середовище (з режимом конфіденційності): все
- Настанови щодо відповідності за галуззю (HIPAA, GDPR, адвокатська таємниця, FERPA, SOX, PCI-DSS, NDA/комерційна таємниця)
- Як налаштувати режим конфіденційності
- Відмова від відповідальності: автори інструменту не є юридичними радниками

### Попередження конфіденційності у схемі інструментів
Оновити описи інструментів `ListToolsRequestSchema`, включивши примітку про конфіденційність для будь-якого інструменту, що повертає текст транскрипції. Це відображається в описах інструментів Claude Desktop і підвищує обізнаність у точці використання.

### Автоматичне очищення тимчасової теки
`%TEMP%\whisper-mcp-jobs\` накопичує файли стану завдань і журнали з часом. Додати автоматичне очищення завершених файлів завдань після налаштованого вікна збереження (типово: 7 днів). Наразі вимагає ручного `Remove-Item` від користувача.

## Заплановано — Міграція на Bun

Перенести середовище виконання з Node.js на [Bun](https://bun.sh) після завершення архітектури конфіденційності і до додавання функцій v2.3.0.

Оскільки Claude Desktop запускає MCP-сервер заново при кожному запуску сеансу, час запуску знаходиться на критичному шляху. Bun виконує TypeScript нативно без кроку компіляції, запускається значно швидше за Node і має швидший введення-виведення.

**Що змінюється:**
- Усунення кроку збірки `tsc` і теки `dist/`
- Користувачі запускають вихідний код TypeScript безпосередньо
- `tsconfig.json` стає необов'язковим
- Оновлення скриптів `package.json`
- Оновлення робочого процесу публікації npm

**Що не змінюється:**
- Вихідний код `src/index.ts` — Bun сумісний з існуючим TypeScript і вбудованими API Node.js
- Уся поведінка інструментів і формати виводу
- Конфігурація Claude Desktop для кінцевих користувачів

**Чому після конфіденційності, до v2.3.0:** Кодова база найлегше піддається міграції зараз. Міграція після додавання більшої кількості інструментів лише збільшує поверхню без вигоди. Архітектура конфіденційності має бути реалізована першою, як зазначено вище.

## Заплановано — v2.3.0: Розширення форматів виводу

### Формат субтитрів VTT
Вивід WebVTT (`.vtt`) разом з SRT. VTT — веб-стандарт, що використовується YouTube, HTML5 `<video>` і більшістю сучасних програвачів. whisper-cli підтримує його нативно. Додати `vtt` як дійсний формат виводу у `transcribe_audio`, `generate_subtitles` і `spawnDetached`. Оновити `buildArgs` і всі відповідні схеми інструментів, README і багатомовну документацію.

### Формат LRC
Вивід у форматі LRC (`.lrc`) текстів пісень/караоке через `-olrc`. Використовується медіапрогравачами для синхронізованого відображення текстів. Нульові витрати на реалізацію — рідний прапорець CLI.

### Формат CSV
Вивід CSV (`.csv`) через `-ocsv`. Структуровані табличні дані з часовою розміткою сегментів — корисні для аналізу нижнього рівня, робочих процесів вирівнювання кліпів та імпорту в табличні інструменти. Нульові витрати на реалізацію — рідний прапорець CLI.

## Заплановано — Майбутні релізи

### TinyDiarize
Підтримка прапорця `--tinydiarize` з варіантами моделей, що підтримують `tdrz` (наприклад `large-v2-tdrz`). На відміну від стерео-прапорця `--diarize`, TinyDiarize працює з моно записами. Потребує завантаження спеціального варіанту моделі. Нижча точність, ніж дiaризація на основі pyannote, але нульові додаткові залежності за межами файлу моделі.

**Статус:** Заплановано. Залежить від підтримки варіантів моделей tdrz у `download_model`.

### Транскрипція URL YouTube
Пряма транскрипція з URL YouTube через yt-dlp. Завантаження аудіо і транскрипція в один крок. Потребує встановленого yt-dlp і наявності в PATH.

**Обмеження проєктування:** yt-dlp є необов'язковим. Інструмент має коректно деградувати з чіткими інструкціями щодо встановлення, якщо його не знайдено. Жодних змін в основній функціональності для користувачів, яким це не потрібно.

### Інструменти робочого процесу відеопроєкту
Для користувачів, що керують великими проєктами відеомонтажу з теками вихідних і відредагованих кліпів:

1. Сканування вихідної теки і підтеки кліпів
2. Нечітке зіставлення транскрипцій відредагованих кліпів з вихідними транскрипціями для визначення точок походження
3. Відображення описових імен файлів, запропонованих Claude на основі вмісту транскрипцій, з вимогою явного підтвердження від користувача перед виконанням будь-якого перейменування
4. Пошук транскрипцій у теці проєкту з результатами за часовим кодом

**Обмеження проєктування:**
- Вихідні файли **ніколи не перейменовуються і не змінюються**
- Усі перейменування вимагають **явного підтвердження користувача**
- Пошук — це окремий інструмент, що може використовуватися незалежно
- Аналіз і зіставлення відбуваються локально — Claude викликається лише коли користувач переглядає результати, мінімізуючи виклики API

**Статус:** Фаза проєктування.

### Розрізнення доповідачів (pyannote-audio)
Повне розрізнення доповідачів у моно з мітками ID доповідача — позначає переходи між доповідачами по всьому запису незалежно від конфігурації каналів. Відрізняється від вбудованого стерео-прапорця `--diarize` (v2.2.0) і TinyDiarize.

**Реалізація:** Потребує [pyannote-audio](https://github.com/pyannote/pyannote-audio) — бібліотеки на основі Python з вимогою токена доступу до моделей Hugging Face. Повністю окремий стек залежностей від конвеєра whisper.cpp.

**Статус:** Необов'язкова розширена функція з власною документацією з налаштування. Не входить до основного пакету.

### Переклад на не-англійські мови
Прапорець `--translate` Whisper орієнтований лише на англійську. Підтримка довільних цільових мов потребує зовнішнього API перекладу або локальної моделі перекладу.

**Варіанти, що розглядаються:** LibreTranslate (можна розгорнути самостійно, локальний пріоритет), локальний LLM-переклад або явна документація поза межами охоплення.

**Статус:** Відкладено, очікує дизайнерського рішення щодо локального пріоритету проти залежності від API.

### Очищення і форматування транскрипції
Конвеєр постобробки:
- Видалення слів-заповнювачів і невдалих початків (необов'язково, під контролем користувача)
- Розриви абзаців на природних межах тем
- Форматування з урахуванням доповідачів у поєднанні з виводом розрізнення
- Експорт у PDF або DOCX

**Статус:** Заплановано. Варіант з урахуванням доповідачів залежить від розрізнення.
