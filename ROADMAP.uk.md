# whisper-windows-mcp — Дорожня карта

Поточна версія: **v2.5.0**

## Принципи проєктування

Ці принципи визначають кожне рішення в цьому проєкті і мають пріоритет над швидкістю додавання функцій.

**Мінімізуйте використання Claude API.** Увесь робочий процес транскрипції — сканування, аналіз, черга, виконання, перевірка, перемикання моделей — має виконуватися з якнайменшою кількістю взаємодій із Claude. Цей інструмент має бути повністю функціональним для користувачів безкоштовного плану Claude, які не платять за підписки Pro або Max. Кожен виклик інструменту витрачає ліміт використання. Проєктуйте відповідно.

**Завжди лише один екземпляр whisper.** Ніколи не запускайте другий процес whisper-cli.exe, поки один вже виконується. Блокування процесу є обов'язковим і не підлягає обговоренню.

**Локальний пріоритет, приватність за замовчуванням.** Аудіо ніколи не покидає комп'ютер. Для основних функцій хмарні API не потрібні. Необов'язкові інтеграції (наприклад, завантаження моделей з Hugging Face) мають бути чітко задокументовані як необов'язкові.

**Явний контроль користувача.** Жодних тихих масових операцій. Руйнівні або незворотні дії потребують підтвердження. Користувач завжди має знати, що станеться, до того, як це відбудеться.

**Unicode-безпечні шляхи.** Усе файлове введення-виведення має правильно обробляти не-ASCII імена файлів, включно з японськими, китайськими символами, емодзі, дужками та іншими спеціальними символами.

**Модульність і компонованість.** Інструменти незалежні. Користувачі використовують те, що їм потрібно. Жодна функція не повинна вимагати іншої для роботи, якщо цього неможливо уникнути.

**Оптимізація перед функціями.** Якщо сумніваєтеся між додаванням функції та зменшенням навантаження на систему чи кількості викликів API — зменшуйте навантаження. Масштабні оптимізаційні проходи дорого коштують. Спроєктуйте архітектуру правильно з першого разу.

### ✅ v2.3.0 — Автопросування пакету, архітектура конфіденційності, розширення форматів виводу

**Автопросування пакету (критичне виправлення помилки):** `start_batch` раніше вимагав активного опитування для просування черги. Тепер до кожного породженого дочірнього процесу whisper-cli прикріплено обробник `on('exit')`. Коли процес завершується, пакет самостійно просувається одразу через зворотний виклик виходу з нульовими витратами на опитування і нульовим споживанням API. М'ютекс запобігає подвійному запуску між паралельними обробником виходу і викликами `check_batch_progress`.

**Архітектура конфіденційності:**
- Змінна середовища `WHISPER_PRIVACY_MODE` — при значенні `true` всі відповіді інструментів повертають лише метадані (ім'я файлу, кількість слів, шлях збереження). Жоден текст транскрипції ніколи не передається до API Claude. Транскрипції існують лише як локальні файли.
- Змінна середовища `WHISPER_CONSENT_ACKNOWLEDGED` — при значенні `true` пригнічує одноразові ворота згоди сеансу для нечутливого контенту.
- Параметр `privacy_mode` для окремого виклику у `transcribe_audio`, `transcribe_batch`, `start_batch` і `check_progress`. Перевизначає глобальну змінну середовища в обох напрямках. Перезапуск не потрібен для перемикання для окремого виклику.
- Ворота режиму конфіденційності (`checkPrivacyGate()`) — спрацьовують перед кожною операцією, коли ефективний режим конфіденційності активний. Зводяться при першому виклику (показують застереження), скидаються при другому (дозволяють). Скидаються після кожної операції. Повністю незалежні від воріт згоди сеансу.
- Ворота згоди сеансу (`transcriptPolicy()`) — спрацьовують один раз за сеанс перед першим викликом, що повертає транскрипцію, у стандартному режимі. Споживаються прапорцем `sessionConsentGiven`.
- `PRIVACY.md` — повна документація відповідності, що охоплює HIPAA, GDPR, адвокатську таємницю, FERPA, SOX, PCI-DSS і NDA/комерційну таємницю.
- Попередження про конфіденційність в описах усіх інструментів, що повертають транскрипцію.

**Розширення форматів виводу:**
- `vtt` — вивід субтитрів WebVTT через `-ovtt`. Доступний у `transcribe_audio`, `generate_subtitles`, `start_batch` і фоновому режимі.
- `lrc` — формат текстів/караоке LRC через `-olrc`. Доступний у `transcribe_audio` і фоновому режимі.
- `csv` — CSV з мітками часу через `-ocsv`. Доступний у `transcribe_audio` і фоновому режимі.
- Типове значення `output_format` змінено з `"text"` на `"timestamps"` у всіх інструментах і шляхах коду. Простий текст тепер увімкнено за вибором.

**Виправлення помилок:**
- Помилка 1: `output_format` не передавався фоновим завданням — використовувалося типове `"text"` незалежно від запитаного формату. Виправлено зміною типового значення на `"timestamps"` і коректним пересиланням.
- Помилка 2: тихий `catch {}` в операції переміщення виводу фонового завдання приховував збої. Додано явну перевірку `existsSync` з детальним повідомленням про збій після переміщення.
- Помилка 3: додано коментар про дизайн у точці фонового запуску, що документує, чому ворота згоди навмисно відкладаються до `check_progress` для не-конфіденційних фонових завдань.

**Додатково:**
- Автоматичне очищення тимчасової теки — `cleanupOldJobFiles()` запускається при старті, видаляє файли `.json` і `.log` старші за 7 днів з `%TEMP%\whisper-mcp-jobs\`.
- `check_config` тепер повідомляє статус режиму конфіденційності.
- Журнал запуску повідомляє про увімкнення/вимкнення режиму конфіденційності.
- Інтерфейс `Job` розширено полем `privacyMode: boolean`.
- Інтерфейс `BatchState` розширено полем `privacyMode: boolean`.
- Тип `BackgroundFormat` виключає `json` (json у фоновому режимі досі не підтримується — відкочується до `text`).

Поріг налаштовується через `WHISPER_FOREGROUND_MAX_SEC`. Оцінки часу виправлено (стара оцінка GPU сильно занижувала прогноз; домінувальну вартість перезавантаження моделі тепер змодельовано — виміряно, а не вгадано).

- Стійкі до колізій ідентифікатори завдань/пакетів/тимчасові (із суфіксом UUID).

**Якість:**

**Визначено для майбутнього випуску:** шлях постійної моделі (напр. `whisper-server` від whisper.cpp), щоб усунути вартість перезавантаження моделі, яка сплачується при кожній транскрипції — велике підвищення пропускної здатності для пакетної/архівної роботи.

### ✅ v2.5.0 — Постійний сервер моделі + TinyDiarize

**Постійний сервер моделі (Фаза 1).** whisper-cli є одноразовим: він перезавантажує повну модель при кожному виклику — v2.4.0 виміряла це перезавантаження як ~110 с на GPU з обмеженою пам'яттю, фіксований податок за файл, який домінує над часом виконання пакетної/архівної роботи. v2.5.0 додає необов'язковий режим резидентної моделі, що тримає модель у пам'яті між транскрипціями.
- Інструмент `whisper_server` (`start` / `stop` / `status`). Резидентний сервер *стає* єдиним екземпляром, зберігаючи правило одного екземпляра whisper: запити серіалізуються до нього, конкурентність не вводиться.
- Блокувальні `transcribe_audio` і `transcribe_batch` маршрутизуються через резидентний сервер по localhost (`127.0.0.1`) через `POST /inference`, пропускаючи вартість перезавантаження. Захист тайм-ауту переднього плану пропускається в режимі сервера (немає перезавантаження, за яке платити).
- `switch_model` гаряче замінює резидентну модель через `POST /load` без перезапуску. `check_config` повідомляє стан сервера; власний сервер завершується при вимкненні для звільнення VRAM.
- Правило один-рушій / спільний-VRAM забезпечується жорстким запобіжником у шляху відокремленого запуску плюс дружніми відмовами: поки сервер працює, фонові завдання, `start_batch`, `generate_subtitles`, вивід `lrc`/`csv` і параметри для окремого запиту, які HTTP API не підтримує (`beam_size`, `best_of`, `word_timestamps`, `diarize`, `tinydiarize`, `vad_model`, `offset_t`, `duration` тощо), відхиляються з повідомленням «спочатку зупиніть сервер» замість тихої деградації.
- Конфігурація: `WHISPER_SERVER_PATH`, `WHISPER_SERVER_PORT` (типово 8571, лише localhost).

**Проєктні обмеження:**
- Явний життєвий цикл: start / stop / status із перевіркою стану. Сервер ніколи не запускається тихо як побічний ефект стороннього виклику.
- Прив'язка лише до localhost — ніколи до маршрутизованого інтерфейсу. Жодного відкриття в мережу (узгоджено з принципом локального пріоритету і посиленням v2.4.0).
- М'яке відкочування: якщо сервер не запущено, транскрипція все одно працює через існуючий одноразовий шлях whisper-cli. Сервер є оптимізацією, а не жорсткою залежністю.
- `switch_model` перезавантажує модель у резидентному сервері (усе одно значно дешевше в перерахунку, ніж перезавантаження на файл).
- Ворота конфіденційності і згоди незмінні — вони знаходяться над механізмом транскрипції.
- Вибір порту з обробкою колізій; чисте вимкнення за SIGINT/SIGTERM разом із існуючим очищенням тимчасових файлів.

**TinyDiarize.** Підтримка `--tinydiarize` з моделями, що підтримують `tdrz`. На відміну від стерео-прапорця `--diarize` (v2.2.0), TinyDiarize позначає зміни доповідача на **моно** записах і не потребує нічого, крім файлу моделі — ні Python, ні зовнішнього сервісу.
- Параметр `tinydiarize` у `transcribe_audio` і `generate_subtitles` (блокувальний і фоновий режими); `--tinydiarize` проведено через обидва конструктори аргументів.
- `small.en-tdrz` додано до `MODEL_REGISTRY`, щоб `download_model` міг завантажувати його з існуючих довірених просторів імен Hugging Face.

## Заплановано — v3.0.0: Набір інструментів постобробки субтитрів

Шар пакетної обробки на чистому TypeScript над SRT / VTT / JSON, які сервер уже видає — без повторної транскрипції, без нових залежностей, один спільний парсер/серіалізатор. Дзеркалить ланцюжок «пакетного перетворення» спеціалізованих редакторів субтитрів (Subtitle Edit, Aegisub), якого не пропонує жоден конкурентний MCP транскрипції. Зокрема прохід виправлення таймінгу націлений на дефекти, які демонструє сирий вивід Whisper — порожні репліки на тиші, перекривні або надто короткі сегменти, дублікати циклів-повторів, надто довгі рядки — тож набір очищає *власний* вивід цього сервера, а не лише імпортовані файли.

- **Виправлення і перевірка таймінгу** — забезпечити мінімальну / максимальну тривалість репліки; виправити перекривні репліки; застосувати мінімальний проміжок між репліками; замостити підпорогові проміжки (розширення до наступної); прибрати порожні репліки; злити дублікати реплік (цикли-повтори whisper); обмежити двома рядками; сортувати + перенумерувати. Плюс немутувальний **звіт лінтингу**, що позначає для кожної репліки швидкість читання (CPS), символи на рядок і порушення кількості рядків відповідно до вибраного профілю (напр. YouTube 42 CPL / 20 CPS, Netflix 42 / 17) — саме той результат, який редактори хочуть перед імпортом.
- **Повторний таймінг** — зсунути / змістити всі репліки; повторний таймінг за частотою кадрів (напр. 23.976 ↔ 25).
- **Переформатування** — злити короткі репліки; розбити довгі рядки до максимуму символів на рядок / символів на секунду, збалансовуючи два рядки замість жадібного розбиття.
- **Перетворення форматів** — конвертувати наявні файли між SRT / VTT / LRC / CSV / Markdown / простим текстом, плюс вивід ASS/SSA (зі стилем за замовчуванням), без повторної транскрипції. Нормалізація UTF-8 / закінчень рядків при записі (задовольняє вимогу UTF-8 YouTube, запобігає мохібаке при повторному імпорті).
- **Очищення тексту** — знайти/замінити (regex за вибором), видалення слів-заповнювачів зі статичного списку слів (не LLM), нормалізація регістру, видалення анотацій для людей з вадами слуху. Строго механічно — усе, що потребує судження (виправлення OCR, висновок про пунктуацію), залишається поза межами; хост Claude обробляє це над поверненим текстом.
- **Форматування міток доповідача** — форматувати наявні стерео / TinyDiarize зміни доповідача як блоки з префіксом доповідача.
- **Зведена статистика** — кількість слів, тривалість, WPM, середній CPS, коефіцієнт тиші.

**Проєктні обмеження:**
- Чистий TypeScript над SRT / VTT / JSON, які сервер уже видає — без повторної транскрипції, без нових залежностей часу виконання, один спільний парсер/серіалізатор.
- Працює лише над наявними файлами субтитрів/транскрипцій — ніколи не викликає whisper чи ffmpeg, ніколи не торкається аудіо.
- Лише детерміновано і на основі правил — без LLM, без хмари, без «розумного» виправлення. Усе, що потребує судження (виправлення OCR, висновок про пунктуацію), залишається поза межами; хост Claude обробляє це над поверненим текстом.
- Неруйнівно — записує нові файли; ніколи не перезаписує джерельний файл на місці без явного підтвердження користувача.
- Прохід лінтингу / перевірки немутувальний — він повідомляє про порушення, ніколи не переписує тихо.
- Лише стандартні формати обміну — ніколи не керує UI редактора.

**Статус:** Заплановано.

Пряме перетворення YouTube на транскрипцію через yt-dlp раніше планувалося. Відкинуто як першокласну функцію, оскільки:
- **Поверхня безпеки:** воно додає завантаження довільних URL і виклик підпроцесу з вводом, керованим користувачем, скасовуючи посилення v2.4.0, яке зменшило саме цю поверхню.
- **Обслуговування:** yt-dlp часто ламається, коли YouTube змінюється — постійне зобов'язання з обслуговування.
- **Локальний пріоритет і ліцензування:** отримання мережевого контенту знаходиться поза межами локального пріоритету, а вбудовування завантажувача в проєкт із комерційною ліцензією — це сіра зона ToS/відповідальності.
- **Надлишковість:** користувачі можуть запустити yt-dlp самостійно і спрямувати `transcribe_audio` на отриманий файл.

**Альтернатива:** задокументовано як рецепт (запустіть yt-dlp, потім транскрибуйте файл) у README / TROUBLESHOOTING, а не як підтримуваний інструмент — робочий процес залишається доступним без володіння залежністю чи поверхнею атаки.
